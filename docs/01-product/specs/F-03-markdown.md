# F-03：富文本编辑器 · Markdown 内容的显示与编辑

- **状态**：已完成
- **日期**：2026-11-12
- **关联**：F-01、F-13、T-022 ~ T-025、ADR-0004

F-03 富文本编辑器包括两部分：Markdown 内容的显示与编辑、多人实时协同。本文只涉及前一部分。前端编辑器和协同服务用同一套编辑器扩展：协同服务靠它在协同状态和 Markdown 之间转换。

## 要解决什么问题

一份文档的内容有三个来源：用户在编辑器里直接编辑，Agent 通过工具读写，用户导入文件（.md、docx、html、txt）。Agent 只读写 Markdown，模型写文档时会大量使用标题、列表、表格、代码块。

编辑器要把这些 Markdown 显示成排好版的富文本；用户在编辑器里的改动，也要能以 Markdown 的形式交给 Agent 读取和修改。这样人和 Agent 才能在同一份文档上交替编辑，谁的改动都不丢格式。

## 做完长什么样

- [x] 下列元素在编辑器里显示为富文本，可以直接编辑。来源可以是 Agent 新建或修改、导入 .md，也可以是导入 docx 和 html：
  - 一到六级标题，前后不需要空行
  - 无序列表（`-`、`*`、`+`）、有序列表、嵌套列表、任务列表（可勾选）
  - 代码块，保留语言标记，块内可以有空行
  - 表格
  - 引用，引用里可以有列表
  - 加粗（`**`、`__`）、斜体（`*`、`_`）、粗斜体、删除线、行内代码、链接、图片、下划线（`<u>`）、分隔线
- [x] 用户在编辑器里编辑这些内容后，Agent 读到的是等价的 Markdown
- [x] Agent 的替换和删除在表格、列表、代码块里都能用
- [x] 已有文档按上述元素正确显示
- [x] 现有测试不退化；smoke 评测的通过率不低于 2026-11-12 自检的基线（实际执行 28 个、通过 26 个）

## 不做什么

- 工具栏上的插入表格、增删行列、任务列表按钮（表格和任务列表能显示、能编辑单元格内容，入口以后再加）
- 代码高亮
- 数学公式、脚注、Mermaid 等扩展语法
- Markdown 源码模式或分栏预览
- 按纸张分页排版（打印、导出 Word 时的分页）

## 设计

### 交互 / 界面

- 编辑器只有富文本视图，用户看不到 Markdown 符号
- 连续页面，不分页：编辑区整片白底，正文在居中的一栏（最宽 760px）里往下延伸
- 表格：单元格可以直接编辑，Tab 键在单元格之间移动
- 任务列表：点复选框切换完成状态，Agent 读到的是 `- [ ]` 或 `- [x]`
- 样式：表格有边框，表头加粗；代码块用等宽字体和浅色背景

### 技术方案

- **涉及模块**：`web/`、`collab-server/`、`api/`（`DocumentParserUtil`）
- **编辑器扩展**：StarterKit（标题一到六级）、Image、TextAlign、TableKit、TaskList、TaskItem（允许嵌套）。`web/src/editor/DocEditor.vue` 和 `collab-server/extensions.js` 两份扩展列表保持一致
- **Markdown 编解码**：`collab-server/markdown.js` 用 `@tiptap/markdown` 的 `MarkdownManager`，从同一份扩展列表生成解析和写回规则。每个扩展自带自己的 Markdown 规则，新增一种元素只需在两份扩展列表里同时加上对应扩展
- **依赖版本**：web 和 collab-server 的 `@tiptap/*` 统一用 3.33.x，加上 `@tiptap/markdown`（底层是 marked）、`@tiptap/extension-table`、`@tiptap/extension-list`。3.28.0 的 `@tiptap/markdown` 在没有编辑器实例的服务端环境里解析标题会报错，3.33.1 正常
- **写法**：按 `@tiptap/markdown` 的默认规则（ADR-0004）。列表用 `-`、加粗用 `**`、斜体用 `*`，表格按列宽补齐空格；正文里的 `\ ` * _ [ ] ~` 加反斜杠，`& < >` 写成 HTML 实体。Agent 读到的、MinIO 里存的都是这种写法
- **Agent 读取**（`/ai/read`）：按顶层节点分块编号，一张表格、一个完整的列表各算一块
- **Agent 替换和删除**（`/ai/replace`、`/ai/delete`）：
  - 只重建命中的那一个顶层块，其余块的协同身份不变，并发编辑照常合并
  - 原文按读到的写法逐字查找，包括转义符
  - 替换后的文本按 CommonMark 解析，不成对的标记当作普通文字保留，内容不会丢，所以不做额外校验
- **字数统计和摘要**：`DocumentParserUtil.markdownToText` 去掉表格分隔、任务标记、代码围栏，把转义符和 HTML 实体还原成字符
- **导入**：
  - .md 直接按上面的规则解析；txt 一行一段，去掉 UTF-8 BOM
  - docx 和 html 转换时保留原标题级别（最多六级），表格转成 Markdown 表格，行内标记可以叠加；html 的嵌套列表按层级缩进，`<pre>` 转成代码块
- **已有文档**：协同服务加载文档时，对没有带编码版本标记的协同状态，把连续的、能还原成原文的段落、标题、简单列表和引用合成一段重新解析，结果不同才替换；编辑器里做出的嵌套结构原样保留。替换走删除再插入，带旧状态重连的客户端不会把旧内容带回来。处理完打上标记并立即保存，之后不再处理；新建的文档建成时就带标记

### 风险与待定问题

- [ ] **Agent 读到的转义符**：`[arXiv:...]` 读到的是 `\[arXiv:...\]`，`R&D` 是 `R&amp;D`，Agent 可能因此改变写法（评测 paper-02 里它不再写引用的方括号）
- [ ] **段落里字面的块标记**：用户在段落里写的「## 第三章」「- 张三负责前端」「2026. 年度计划」不会被转义，Agent 读到的是标题、列表；Agent 改过这一段后会变成对应格式
- [ ] **已有文档里的字面符号**：没有标记的旧文档按 Markdown 重新解析，用户在编辑器里直接输入的 `*星号*`、纯文本导入（比如 PDF 文字）里形如 `1. Introduction` 的行，会被解析成格式或列表
- **包体积**：编辑器所在的分包从 540 KB 增加到 624 KB（gzip 197 KB）
