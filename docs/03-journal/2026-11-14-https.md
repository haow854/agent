# 2026-11-14 · HTTPS：Let's Encrypt 的 IP 证书

- **目标**：演示环境上 HTTPS（T-033）
- **结果**：
  - 比较了 IP 证书、域名加 ICP 备案、前端放 GitHub Pages，选 IP 证书（ADR-0006）；免费域名指向国内服务器同样要备案，不可行
  - spec F-17 加「HTTPS」一节，验收标准改成 `https://<服务器IP>`、公网开放 80 和 443、证书自动续期
  - compose 加常驻的 `certbot/certbot:v5.9.0`，主循环在 `deploy/certbot.sh`：没有证书时用 `--ip-address`、`--preferred-profile shortlived`、webroot 申请，失败 1 小时后重试；有证书后每 12 小时 `certbot renew`，按 ARI 决定什么时候真的续；不设 `PUBLIC_IP` 时空等
  - web 的 nginx 拆成 `app.conf`（路由）、`http.conf`、`https.conf`；`docagent-site` 按证书是否存在选配置，启动时选一次，之后每 5 分钟检查，证书从无到有或内容变了就换配置并 `nginx -s reload`。注册的 nginx 拦截早已移到后端，配置不再需要模板替换
  - 本地验证（单独起 web 容器，证书卷里按 certbot 的目录结构放自签证书）：没有证书时 HTTP 提供应用和验证文件；放进证书后切到 HTTPS，HTTP 301 到 https，80 端口仍提供验证文件，ALPN 协商出 h2；换第二张证书后不手动触发，后台循环 260 秒后自己重新加载，对外换成新证书；证书没变时脚本什么都不做；容器重启后仍是 HTTPS
  - certbot 5.9.0 认得全部参数（`--register-unsafely-without-email` 不在帮助里，但仍接受）；不设 `PUBLIC_IP` 时循环空等，收到 TERM 正常退出
  - F-17 的服务器初始化补上：部署用户加进 `docker` 组、`/opt/docagent` 交给部署用户
- **决策**：[ADR-0006](../04-adr/0006-https-ip-certificate.md) HTTPS 先用 Let's Encrypt 的 IP 证书
- **问题**：本地拿不到 Let's Encrypt 的真证书（要从公网访问 80 端口），真证书的签发和续期没验证过
- **遗留**：
  - 服务器上首次部署后看 `docker compose logs certbot`，确认证书签下来、几分钟内切到 HTTPS，几天后确认续期过一次（T-005、T-033）
  - 部署前在本地按 compose 完整演练一次（api 镜像、注册、演示账号、HTTPS 都改过）
