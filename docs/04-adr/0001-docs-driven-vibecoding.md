# ADR-0001：用仓库内的 docs/ 作为 Vibe Coding 知识库

- **状态**：已采纳
- **日期**：2026-11-11
- **关联**：T-004

## 背景

项目以 Vibe Coding 方式推进（以 AI 为主力编写代码）。AI 每次会话都从零开始，需要一个它能直接读写的地方，集中管理产品设计、功能决策和待办事项。

## 决定

在仓库内建立 `docs/`，以本地 LLM Wiki 的形式管理。按编号目录组织，编号前缀即阅读顺序：

| 目录 | 回答的问题 |
| --- | --- |
| `01-product/` | 是什么、怎么设计（含功能地图和 specs） |
| `02-todos/` | 做什么 |
| `03-journal/` | 做到哪 |
| `04-adr/` | 为什么这么选 |
| `05-postmortems/` | 踩过什么坑、以后怎么防 |

根目录 `AGENTS.md` 写明各目录归属，`CLAUDE.md` 引用 `AGENTS.md`，保证 AI 会话自动加载入口。

## 影响

- 每次会话开始和结束要花几分钟维护文档
- `docs/` 随代码一起提交（已从 `.gitignore` 中移除）
- 后续：补录既有架构决策（T-010）
