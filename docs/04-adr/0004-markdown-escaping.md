# ADR-0004：Markdown 写法使用 TipTap 的默认转义

- **状态**：已采纳
- **日期**：2026-11-13
- **关联**：F-03、01-product/specs/F-03-markdown.md

## 背景

协同服务把编辑器内容写成 Markdown，给 Agent 读取，也存进 MinIO 供摘要、版本历史、评测使用。Markdown 用符号表示格式，正文里本身就有的符号（`*`、`_`、`[`、`&`、行首的 `##` 等）写出去后，可能被读成斜体、链接、标题，所以要转义（加反斜杠，或写成 HTML 实体）。

`@tiptap/markdown` 的默认写法只转义行内符号：`\ ` * _ [ ] ~` 加反斜杠，`& < >` 写成 HTML 实体；行首的 `#`、`-`、`1.`、`---` 这类块标记不转义。

## 备选方案

### TipTap 默认转义

- 优点：不维护自己的转换逻辑，跟随库的实现
- 缺点：
  - 不会被误读的符号也转义：`[arXiv:1810.04805]` 写成 `\[arXiv:1810.04805\]`，`R&D` 写成 `R&amp;D`。Agent 读到后会改变自己的写法，评测 paper-02 里它因此不再写引用的方括号；按文字匹配的评测检查也对不上
  - 行首块标记不转义：段落里字面的「## 第三章」「- 张三负责前端」「2026. 年度计划」，Agent 读到的是标题、列表；Agent 改过这一段后，它在编辑器里就真的变成标题、列表

### 只在必要时转义

每个块先原样写出、解析回来比对，对不上才转义，同时补上行首块标记的转义。

- 优点：常见文字保持原样，字面的块标记也不会被误读
- 缺点：要在库之外自己维护一层转换逻辑

### 一律不转义

- 优点：Agent 读到的永远是原文
- 缺点：字面的 `*星号*`、`[文字](地址)` 写出去再解析，会变成斜体、链接，内容被改

## 决定

使用 TipTap 的默认转义，不在库之外加自己的转换逻辑。

## 影响

- 转换代码只有对库的一层调用，库升级、修复后直接受益
- Agent 读到的正文带反斜杠和 HTML 实体，个别任务（如按固定格式改写引用）可能因此写错
- 段落里字面的块标记在 Agent 改过那一段后会变成对应格式，这是已知局限
- 字数统计和摘要由 `DocumentParserUtil.markdownToText` 还原转义，用户看不到反斜杠
