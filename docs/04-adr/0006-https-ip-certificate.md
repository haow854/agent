# ADR-0006：HTTPS 先用 Let's Encrypt 的 IP 证书

- **状态**：已采纳
- **日期**：2026-11-14
- **关联**：F-17、T-005、01-product/specs/F-17-deployment.md

## 背景

演示环境要从公网访问，登录时的密码、请求头里的令牌、文档内容都要加密传输；只走 HTTP 时浏览器还会标「不安全」。服务器是腾讯云上海地域的轻量应用服务器，还没有域名。

域名解析到国内服务器必须先做 ICP 备案，否则腾讯云按 `Host` 和 SNI 拦截这个域名在 80/443 上的访问。免费的子域名（DuckDNS、sslip.io、eu.org 等）不在自己名下，没法备案。

## 备选方案

### Let's Encrypt 的 IP 证书

Let's Encrypt 从 2026 年 1 月起正式给 IP 地址签证书，只能用 `shortlived` 档，约 6 天有效；certbot 5.4 起支持 IP 加 webroot。

- 优点：不需要域名和备案，部署当天就有 HTTPS；前后端仍在同一个源下，代码不用改
- 缺点：网址是 IP；证书 6 天就过期，自动续期必须一直正常

### 域名加 ICP 备案

- 优点：网址正规；证书 90 天有效
- 缺点：域名实名加备案要 1～3 周，还要做公安备案、页面挂备案号

### 前端放 GitHub Pages

拿到 `<用户名>.github.io` 和它自带的 HTTPS，后端仍在腾讯云。

- 优点：网址比 IP 好看，不用备案
- 缺点：https 页面不能请求 http 的后端和 `ws://`，后端照样要证书；前后端分开后要配置跨域、改前端的接口地址；GitHub Pages 在国内访问不稳定

## 决定

先用 Let's Encrypt 的 IP 证书。它是唯一不用等备案、也不用拆开前后端的做法；以后备案下来，nginx 换成域名证书即可，签发和续期的机制不变。

## 影响

- compose 多一个常驻的 certbot 服务，web 多发布 443 端口
- nginx 按证书是否存在选择 HTTP 或 HTTPS 配置，本地没有证书时照旧走 HTTP
- 证书过期风险：certbot 停了或续期失败几天后，浏览器会拦截访问，部署后要看一次续期日志
- 不开 HSTS，否则证书出问题时用户连「继续访问」都点不了
